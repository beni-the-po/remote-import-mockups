Remote Import Notes

Agreements (LPD-104518)

  • Export and Remote Import are separate processes, executed in two separate steps. No changes to the export process.
  • New kebab option on a Successful export: Send to Environment(s). It can be executed as many times as the user wants.
  • The user names the remote import (required). That name is what every target environment shows in its import processes list.
  • Company scope: any environment can be selected, with or without sites. No site selection.
  • Site scope: only environments with sites; one or more sites per environment.
  • One toast on start, regardless of how many destinations were selected.
  • Each remote environment reports back its result; one notification per result, with the environment name.
  • Import details live in the remote environment; the toast and the notifications link there.
  • Remote environments are configured in Instance Settings. Port is required. Sites are optional; empty site rows are ignored and partially filled ones block Save.

Open Questions

  • Final action name: "Send to Environment(s)" or "Propagate"? (The prototype uses "Send to Environment(s)".)
  • Company-scope modal title: the prototype uses "Send to Environment(s)".
  • Is the Name prefilled with the export name? (The prototype starts it empty.)
  • View Details: the prototype opens a details page (general info, export configuration, content counts). The "Remote Imports" history section is a proposal, not in the design.
  • With several destinations, "View in destination(s)" expands a list of links in the toast. Is that the intended behavior?
  • Do multiple remote imports run in parallel? (The prototype simulates parallel runs.)
  • Can the environment selector be reused for remote staging or per-asset remote import?
